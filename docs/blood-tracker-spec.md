# 혈액검사 기록 관리 웹앱 — 기획/설계 문서

> Claude Code에서 이어서 개발하기 위한 문서입니다. 함께 전달한 `blood-tracker-prototype.html`이 현재 화면 프로토타입이며, 이 문서는 그 프로토타입을 실제 앱으로 발전시키는 기준입니다.

## 1. 목적

3개월 단위로 받는 혈액검사 결과를 한곳에 모아 **수치와 경과를 그래프로 보고 관리**한다. 검사마다 포함 항목이 다르다는 점(기본 검사, 갑상선 추가, 종합 등)이 핵심 제약이며, 항목이 없는 검사가 있어도 추이가 자연스럽게 이어져야 한다.

- 사용자: 한 브라우저에서 본인과 가족 여러 명의 데이터를 관리하는 개인 도구
- 환경: 웹페이지(PC·모바일 브라우저), 한국어 UI
- 민감 정보(건강 데이터)이므로 **로컬 우선 저장, 외부 전송 없음**을 기본 원칙으로 한다.

## 2. 핵심 설계 결정

1. **"검사 종류"는 저장하지 않고 파생한다.** 한 번의 검사는 `포함된 그룹 목록`만 가진다. 화면의 라벨(기본 / 기본 + 갑상선 / 종합)은 그룹 조합에서 계산한다. 새 검사 종류가 생겨도 스키마 변경이 필요 없다.
2. **항목(marker)은 마스터 데이터로 분리한다.** 이름, 단위, 참고 범위, 소수 자릿수, 소속 그룹을 마스터가 가지고, 측정값은 `(검사, 항목, 값)`만 가진다.
3. **측정값이 없는 칸은 0이나 보간이 아니라 "없음"이다.** 그래프는 측정된 점만 잇고, 미측정 날짜는 흐리게 표시한다. 비교표는 "—"로 비운다.
4. **참고 범위는 항목 마스터에 두되 사용자가 수정할 수 있어야 한다.** 검사기관·성별마다 다르다. 프로토타입의 범위는 예시 값이다.
5. **상태 판정은 값과 범위로만 계산한다.** `낮음 / 정상 / 높음` 외에 의학적 해석 문구는 넣지 않는다.

## 3. 도메인 모델

### 프로필

검사 데이터는 사람별로 분리한다. 화면 상단의 현재 프로필 선택기에 선택된 사람의 검사만 표시하며, 새 가족을 추가하면 빈 검사 목록으로 시작한다.

```ts
type Profile = {
  id: string;
  name: string;
  tests: Test[];
};

type AppStore = {
  schemaVersion: 2;
  selectedProfileId: string;
  profiles: Profile[];
  labs: string[];          // 검사결과지에 적힌 기관명 목록
  referenceRanges: Record<string, Record<string, ReferenceRange>>;
};
```

- 프로필 전환 시 차트, 요약, 카드, 비교표, 검사 입력 대상이 모두 선택된 프로필 기준으로 바뀐다.
- 검사기관은 검사마다 저장한다. 기본 화면은 `전체 기관`으로 두어 같은 항목의 추이를 기관이 달라도 함께 볼 수 있다.
- 검사기관 필터를 선택하면 요약, 추이, 카드, 비교표가 해당 기관의 검사만 표시한다.
- 같은 날짜라도 검사기관이 다르면 별도 검사로 저장하며, 같은 날짜·같은 기관의 입력만 기존 검사에 병합한다.
- 검사 간격은 검사 결과에 기록하는 기본값(3개월·6개월·1년·2년)이며, 실제 검사일을 강제하지 않는다. 다음 검사 표시는 최근 검사일에 기본 간격을 더한 예상 시점이다.
- 기관명은 사용자가 검사결과지의 표기를 그대로 등록하고, 기관 등록 화면에서 해당 기관의 참고 범위도 함께 관리한다. 이후 결과 입력에서는 등록 목록에서 기관을 선택한다.
- 기존 단일 사용자 저장 데이터는 최초 실행 시 `나` 프로필로 자동 이전한다.
- 프로필 이름은 가족 식별용 표시 이름이며, 주민등록번호 등 불필요한 개인정보는 저장하지 않는다.

| 개체 | 설명 |
|---|---|
| Group | 항목 묶음. 혈당, 지질, 간기능, 신장·요산, 혈구, 갑상선, 비타민·염증 (사용자가 추가·수정 가능) |
| Marker | 검사 항목. 예: 공복혈당, HbA1c, LDL, TSH |
| Test | 한 번의 검사. 검사일, 포함 그룹, (선택) 검사기관, 메모 |
| Result | 한 검사의 한 항목 측정값 |

### 데이터 스키마 (JSON 기준, 저장소가 바뀌어도 동일 구조 유지)

```ts
type Group  = { id: string; name: string; order: number };

type Marker = {
  id: string;            // 'fbs', 'a1c', ...
  groupId: string;
  name: string;          // '공복혈당'
  en?: string;           // 'Fasting Glucose'
  unit: string;          // 'mg/dL'
  lo: number | null;     // 참고 범위 하한 (없으면 null)
  hi: number | null;     // 참고 범위 상한 (없으면 null)
  refLabel?: string;     // '200 미만' 처럼 표시용 문구 (선택)
  dec: number;           // 표시 소수 자릿수
  archived?: boolean;    // 더 이상 측정하지 않는 항목
};

type Test = {
  id: string;
  date: string;          // 실제 검진일·검사일 'YYYY-MM-DD'
  groupIds: string[];    // 이 검사에 포함된 그룹
  lab?: string;          // 주치의 병원, 혈액원, 국민건강검진 등
  intervalMonths?: number; // 다음 검사 예상 간격. 실제 예약일이 아님
  nextAppointmentDate?: string; // 실제 다음 예약일. 없으면 일정 미확정
  note?: string;
};

type Result = { testId: string; markerId: string; value: number };

type ReferenceRange = {
  lo: number | null;
  hi: number | null;
  refLabel?: string;
};
```

프로토타입은 `tests[].v = { markerId: value }` 형태로 Result를 Test 안에 합쳐 둔 단순 구조다. 실제 앱에서는 위 정규화 구조로 옮기되 화면 로직은 그대로 재사용한다.

### 파생 값 (저장하지 않음)

- `testLabel(test)`: 7개 그룹 모두 → "종합", 기본 4그룹(혈당·지질·간기능·신장) 포함 → "기본 + 나머지 그룹", 그 외 → 그룹명 나열
- `status(marker, value)`: `value < lo` → 낮음, `value > hi` → 높음, 그 외 정상
- `nextDue`: 최근 검사일 + 해당 검사에 저장된 기본 간격. 실제 검사일이나 예약일로 해석하지 않는다.
- 다음 검진 표시는 실제 예약일이 있으면 예약일을, 없으면 `일정 미확정`을 표시하고 예상 시점을 보조 정보로 표시한다.
- 참고 범위는 기본 항목 범위를 사용하되, 기관별로 저장된 범위가 있으면 해당 기관의 범위를 우선한다.

## 4. 화면 구성 (프로토타입 기준)

위에서 아래 순서로 구성한다.

1. **헤더**: 제목, 현재 프로필 선택기, `+ 가족 추가`, 프로필 이름 변경, 현재 프로필 삭제, 현재 프로필 데이터 초기화, `+ 검사 결과 추가` 버튼. 본인 프로필은 `내 데이터 초기화`로 표시한다.
2. **요약 띠** (3칸): 최근 검사(날짜·종류·항목 수·누적 횟수) / 다음 검사 예상 시점(D-day) / 참고 범위 밖 항목(항목별 최근 값 기준)
3. **추이 패널**: 선택한 항목의 이름·최근 값·상태·참고 범위·직전 대비 + 시계열 차트
4. **항목별 현황**: 그룹 필터 칩 + 그룹별 항목 카드(최근 값, 상태, 미니 추이선). 카드를 누르면 추이 패널이 바뀐다.
5. **검사일별 비교표**: 행 = 항목(그룹 소제목), 열 = 검사일(아래에 검사 종류·검사기관 라벨). 첫 열 고정, 가로 스크롤은 최신 열이 보이도록 오른쪽 끝에서 시작. 기관 필터로 특정 기관만 볼 수 있다.
6. **결과 입력 폼**: 실제 검진일, 등록된 검사기관 선택, 다음 실제 예약일(선택), 기본 간격, 검사 목적 메모, 검사 종류 프리셋, 그룹 체크, 선택된 그룹의 항목 입력칸(placeholder에 참고 범위)
7. **검사기관 및 참고 범위 관리**: 기관 등록·삭제, 기관별 항목 참고 범위 입력·수정. 기관 삭제 시 기존 검사 기록은 보존하고 기관 등록 정보와 참고 범위만 삭제한다.
   삭제된 기관과 유사한 이름을 다시 등록하면 과거 기록의 기관명을 보여주고, 기존 기관명 복원을 확인한다. 복원하면 기존 기록과 다시 연결되며, 새 이름으로 진행하면 별도 기관이 된다.
8. **데이터 관리**: 전체 프로필·검사·기관·참고 범위를 JSON으로 백업 저장하고, 백업 파일로 복원한다. 현재 프로필 삭제는 확인 후 실행하며 마지막 프로필은 삭제할 수 없다. 프로필은 유지한 채 현재 가족의 검사 기록만 초기화할 수 있다.

### 차트 스펙

- X축: 시간 비례. 전체 검사일 + 다음 예정일(점선)까지. 이 항목을 측정하지 않은 날짜는 흐린 라벨과 "미측정" 표시.
- Y축: 데이터와 참고 범위를 모두 포함하도록 자동 계산, 여백 상 18% / 하 12%, 눈금은 4구간 기준 nice tick.
- 참고 범위는 초록 띠로 표시. 한쪽 경계만 있으면 차트 끝까지 확장.
- 점 색은 상태(정상/높음/낮음), 모든 점에 값 라벨, 마지막 점은 크게.
- 색만으로 구분하지 않는다: 상태에 `높음 ▲ / 낮음 ▼` 글리프와 텍스트를 함께 표시.
- 컨테이너 실제 너비로 다시 그린다(ResizeObserver). 모바일(≈400px)에서 라벨이 겹치지 않아야 한다.

### 디자인 토큰

- 라이트/다크 모두 지원 (CSS 변수, `prefers-color-scheme`)
- 폰트: IBM Plex Sans KR(본문) + IBM Plex Mono(날짜·수치 보조)
- 강조색은 인디고 계열 1개, 상태색(초록/주황빨강/호박색)은 강조색과 분리
- 수치 열은 `font-variant-numeric: tabular-nums`

## 5. 프로토타입 현황

**구현됨**
- 위 화면 전체와 샘플 데이터(7회 검사, 20개 항목, 7개 그룹)
- 프로필별 검사 데이터 저장, 프로필 전환, 가족 프로필 추가, 기존 단일 사용자 데이터 자동 이전
- 그룹 필터, 항목 선택, 차트 리사이즈 대응, 라이트/다크
- 결과 추가 폼(검사기관·프리셋 → 그룹 체크 → 항목 입력), 같은 날짜·같은 기관 입력 시 병합, `localStorage` 저장, 샘플 초기화
- 검사기관 등록·삭제 목록·선택, 기관별 참고 범위 관리, 기관별 필터, 전체 기관 통합 추이·비교표
- 실제 검진일·다음 예약일·예상 간격·검사 목적 메모 분리
- 기관별 참고 범위 저장 및 상태·차트 반영
- 가족 프로필 삭제(확인창·마지막 프로필 삭제 방지), 현재 가족 데이터 초기화, JSON 데이터 백업·복원
- 검사 기록 수정·삭제, 프로필 이름 변경, 미래 날짜·비정상 수치 입력 검증

**미구현 (아래 로드맵 대상)**
- 항목/그룹 편집, 검사 수정·삭제
- 여러 항목 겹쳐 보기, 기간 필터
- 검사 결과지 업로드·자동 입력
- 테스트 코드, 빌드 환경 (현재는 단일 HTML 파일)

## 6. 개발 로드맵

### Phase 1 — 프로젝트 정리 (기반)
- 단일 HTML을 모듈로 분리: `data/`(스키마·마스터·샘플), `lib/`(status, label, nextDue, ticks), `components/`(Summary, Chart, Card, Matrix, Form)
- 순수 함수(`status`, `testLabel`, `niceTicks`, `addMonths`)에 단위 테스트 작성. 경계값(범위 하한/상한과 같은 값), 소수 비교, 그룹 조합별 라벨이 핵심.
- 기존 화면과 동작이 같은지 확인

### Phase 2 — 데이터 관리
- 검사 수정·삭제 (비교표 열 헤더에서 진입)
- 항목 마스터 편집: 참고 범위, 단위, 표시 이름, 그룹 이동, 새 항목 추가, 보관(archived)
- JSON 내보내기 / 가져오기 (스키마 버전 필드 포함), CSV 내보내기
- 입력 검증: 음수·비정상적으로 큰 값 경고, 같은 날짜 중복 시 병합 여부 확인을 화면 안에서 처리

### Phase 3 — 분석 기능
- 기간 필터 (최근 1년 / 전체), 항목 2~3개 겹쳐 보기(값을 참고 범위 기준 %로 정규화)
- 항목별 메모, 검사별 메모(약 복용, 생활 변화 등)를 차트 마커로 표시
- 추세 요약 문구: 최근 3회 연속 상승/하락 등 사실만 표기(해석 문구 제외)

### Phase 4 — 저장소와 배포
- 저장소 선택지는 아래 7번 참조
- 정적 호스팅 배포, 백업 알림("마지막 내보내기 N일 전")

### Phase 5 — 선택 과제
- 검사 결과지(사진·PDF) 읽어서 입력 초안 만들기, 사용자가 확인 후 저장
- 다음 검사 알림(캘린더 파일 `.ics` 내보내기)

## 7. 기술 선택지

| 항목 | 권장 | 대안 |
|---|---|---|
| 프런트엔드 | Vite + TypeScript, 프레임워크는 가볍게(Preact/React) 또는 바닐라 | 현재 구조를 유지하며 ES 모듈로만 분리 |
| 차트 | 현재 방식 유지(직접 SVG). 항목 수가 적고 참고 범위 띠, 미측정 표시 등 맞춤 요구가 많음 | uPlot, Chart.js (겹쳐 보기 단계에서 재검토) |
| 저장 | **IndexedDB 또는 localStorage + JSON 내보내기** (로컬 우선) | 서버 DB(기기 간 동기화가 필요할 때), 이 경우 인증·암호화 필수 |
| 배포 | 정적 호스팅 | 로컬 파일로만 사용 |

건강 데이터이므로 서버에 저장하는 경우 전송·저장 암호화, 접근 제어, 백업 정책을 먼저 정한다. 외부 분석 도구나 광고 스크립트는 넣지 않는다.

## 8. 결정이 필요한 사항 (열린 질문)

1. 실제로 관리할 검사 종류와 항목 목록은? (프로토타입 20개 항목은 예시)
2. 참고 범위는 검사기관 결과지 기준으로 직접 입력할지, 항목별 기본값을 둘지?
3. 기기 간 동기화(PC·휴대폰)가 필요한가? 필요하면 서버 저장, 아니면 로컬 + 내보내기로 충분
4. 과거 결과를 한꺼번에 입력하는 방법: 폼 반복 입력 / CSV 가져오기 / 결과지 자동 입력
5. 검사 간격(3개월)을 항목 그룹별로 다르게 둘지 (예: 갑상선은 6개월)
6. 성별·나이에 따른 참고 범위 분기가 필요한가?
